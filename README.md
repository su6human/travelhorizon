# TravelHorizon

Сайт туристической компании из Бишкека, сделанный по техническому заданию «TravelHorizon — Technical Requirements».
В проекте шесть публичных страниц на английском, русском и кыргызском языках, форма запроса с расчётом стоимости и отправкой заявки в Telegram, а также защищённый редактор текстов.

Стек: HTML, CSS, чистый JavaScript и Node.js 20+ (встроенный модуль `http`). **Внешних зависимостей нет.**

## Структура

```
server.js              сервер: статика, API, вход, CSRF, лимиты, Telegram, хранение текстов
package.json           npm start / npm test, Node >= 20
render.yaml            Blueprint для Render (сервис + постоянный диск)
.env.example           список переменных окружения
test/server.test.js    25 автотестов (node:test)
scripts/download-images.js  скачивает фото в public/images/ (npm run images)
data/                  сюда сохраняется content.json, если CONTENT_FILE не задан
public/
  index.html           Главная
  tours.html           Туры + фильтры
  about.html           О нас + авторы фото
  partners.html        Партнёрам
  experiences.html     Впечатления
  contacts.html        Форма запроса + расчёт стоимости
  admin-login.html     Вход в редактор
  admin.html           Редактор сайта
  404.html
  styles.css           все стили
  script.js            переводы, фильтры, расчёт, форма, редактор
  i18n.js              встроенные тексты EN / RU / KY
  data.js              туры, цены, сезоны, фото (единый источник данных)
  boot.js              выбирает язык до отрисовки страницы
  images/              сюда можно положить свои фото (см. ниже)
```

## Локальный запуск

```bash
npm start                      # http://localhost:3000
npm test                       # автотесты
npm run images                 # скачать фото в public/images/
```

Чтобы проверить вход в редактор и Telegram локально, задайте переменные:

```bash
ADMIN_USERNAME=admin ADMIN_PASSWORD='минимум-12-символов' \
TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... npm start
```

## Деплой на Render

1. Загрузите папку проекта в новый репозиторий GitHub. Файлы `.env` и `data/content.json` уже исключены в `.gitignore`.
2. В Render выберите **New → Web Service** и подключите репозиторий. Можно выбрать и **New → Blueprint**, тогда Render возьмёт настройки из `render.yaml`.
3. Настройки сервиса:
   | Параметр | Значение |
   |---|---|
   | Runtime | Node |
   | Build Command | `npm install` |
   | Start Command | `npm start` |
   | Health Check Path | `/healthz` |
4. В разделе **Environment** добавьте переменные:
   | Переменная | Зачем |
   |---|---|
   | `NODE_ENV` | `production` (включает Secure-cookie и HSTS) |
   | `ADMIN_USERNAME` | логин редактора |
   | `ADMIN_PASSWORD` | пароль редактора, **не короче 12 символов** |
   | `TELEGRAM_BOT_TOKEN` | токен бота |
   | `TELEGRAM_CHAT_ID` | чат, куда приходят заявки |
   | `CONTENT_FILE` | `/var/data/content.json` (путь на постоянном диске) |
   | `TELEGRAM_THREAD_ID` | необязательно: номер темы, если чат — группа с темами |
   | `TELEGRAM_MESSAGE_LANG` | необязательно: `ru` (по умолчанию) или `en` |
5. **Постоянный диск.** В разделе **Disks** добавьте диск с Mount Path `/var/data`. Без него правки из редактора пропадут после перезапуска или нового деплоя: файловая система Render временная. Диски доступны на платных тарифах, начиная со Starter.
6. После деплоя откройте `https://ваш-сайт.onrender.com/healthz`. Должно быть `"telegram": true` и `"admin": true`.

`PORT` задаёт сам Render, сервер слушает `0.0.0.0`.

## Подключение Telegram-бота (тот же, что у redonyx)

Сайт отправляет заявки через Telegram Bot API со стороны сервера. Браузер токен никогда не видит. Чтобы заявки приходили в того же бота и в тот же чат, что у redonyx:

1. Откройте в Render сервис **redonyx → Environment**.
2. Скопируйте оттуда значения токена бота и ID чата. Они могут называться иначе, например `BOT_TOKEN` или `CHAT_ID`.
3. Вставьте их в сервис TravelHorizon как `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` и сохраните. Render перезапустит сервис.
4. Отправьте тестовую заявку со страницы «Контакты».

Важно знать:

- Один токен можно спокойно использовать на двух сайтах. Отправка сообщений (`sendMessage`) не мешает работе redonyx, даже если там бот принимает команды через webhook или polling.
- Заявки с двух сайтов придут в один чат. Сообщение начинается с «**Новая заявка с сайта TravelHorizon**», так что их легко различать. Если чат — группа с темами, можно направлять заявки в отдельную тему через `TELEGRAM_THREAD_ID`.
- Если чат — группа, бот должен быть её участником. ID группы обычно начинается с `-100…`.
- Если Telegram недоступен или токен неверный, сайт продолжает работать, а форма показывает понятную ошибку (A18). Причина пишется в логи Render, сам токен в логи не попадает.

Пример сообщения в чате:

```
Новая заявка с сайта TravelHorizon

Имя: Айгерим
Email: aigerim@example.com
Тур: Сон-Куль без спешки (song)
Путешественников: 4
Интерес: Общий вопрос о туре
Язык сайта: RU
Оценка: USD 740 × 4 = USD 2,960

Сообщение:
Конец июня, вегетарианское питание.
```

## Редактор сайта

Ссылка «Редактор сайта» есть в подвале, редактор открывается по адресу `/admin.html`. Без входа сервер перенаправляет на страницу входа.

- Выберите язык (English / Русский / Кыргызча) и правьте тексты. Поля сгруппированы по разделам, есть поиск.
- Изменённое поле помечается, рядом показан исходный текст и кнопка «Вернуть исходный».
- «Сохранить изменения»: посетители сразу видят новый текст.
- «Скачать резервную копию» и «Загрузить резервную копию»: JSON-файл. После загрузки тексты можно проверить и затем сохранить.
- «Вернуть исходные тексты»: удаляет все сохранённые правки. Нужно нажать дважды.
- Сессия живёт 12 часов, хранится в памяти сервера и заканчивается при перезапуске. После 5 неверных паролей вход блокируется на 15 минут.

**Заполните контакты.** В разделе «Контакты» редактора есть поля `contacts.email.value`, `contacts.phone.value` и `contacts.telegram.value`. Пока они пустые, эти строки на сайте скрыты. Email и телефон станут кликабельными, Telegram можно указать как `@username`.

## Цены, сезоны, фото

Цены, длительность, сезоны и категории туров хранятся в одном месте, в `public/data.js`. Оттуда их берут страницы туров, расчёт стоимости в форме и сообщение в Telegram, поэтому расхождений не будет. По ТЗ (п. 15.1) цены ориентировочные: проверьте их перед публикацией.

**Фото** — реальные снимки Кыргызстана с Wikimedia Commons по лицензиям Creative Commons. Авторы и лицензии указаны на странице «О нас» в блоке «Авторы фотографий». Каждое фото отдаётся по адресу `/img/<ключ>`: сначала берётся файл из `public/images/`, а если его нет — снимок с Wikimedia.

**Скачайте фото в проект один раз** (так надёжнее и быстрее, чем грузить их с Wikimedia):

```
npm run images
git add .
git commit -m "Фото"
git push
```

Команда сохранит 11 фото в `public/images/` и напишет, какие скачались. `npm run images -- --force` скачает всё заново.

Чтобы заменить фото своим:

1. Положите файл в `public/images/` с именем ключа, например `public/images/hero.jpg` или `tour-jyrgalan.webp`. Сервер сам возьмёт локальный файл вместо Wikimedia.
2. Обновите автора и лицензию для этого ключа в `public/data.js`, иначе в списке авторов останется старая подпись.

Ключи фото: `hero`, `tour-ala`, `tour-song`, `tour-issyk`, `tour-jyrgalan`, `exp-horse`, `exp-yurt`, `exp-food`, `exp-trek`, `about`, `partners`.

Своего фото Джыргалана на Commons не нашлось, поэтому у этого тура стоит снимок лошадей на тропе в горах Каракола, и подпись честно указывает место. Его лучше всего заменить первым. Свои фото работают быстрее (NFR-02): сожмите их до ширины около 1600 px.

## Соответствие ТЗ

| Требование | Где реализовано |
|---|---|
| FR-01, FR-02 | шесть страниц, общая навигация, текущий пункт отмечен |
| FR-03 – FR-05 | `i18n.js`, `script.js`: EN/RU/KY, язык сохраняется в localStorage, если перевода нет — показывается английский текст |
| FR-06 – FR-08 | `tours.html`: 4 тура, фильтры, счётчик с правильным множественным числом, пустое состояние; ссылки `?tour=` |
| FR-09, FR-10 | `experiences.html`, `partners.html`: ссылки `?interest=` |
| FR-11 – FR-15 | форма, проверка 1–20, расчёт в формате выбранного языка, отправка JSON на `/api/contact` |
| FR-16, FR-17 | валидация на сервере, Telegram, статус «отправлено» или ошибка |
| FR-18 – FR-22 | вход, сессия 12 ч, HttpOnly + SameSite=Strict (+ Secure в production), проверка origin и CSRF |
| FR-23, FR-24 | `GET /api/content`, лимиты на размер запросов и частоту входа и отправки форм |
| FR-25 | `CONTENT_FILE` + диск Render, атомарная запись |
| NFR-01 – NFR-15 | адаптивная вёрстка без горизонтальной прокрутки, подписи полей и `aria-live`, CSP и заголовки безопасности, секреты только в окружении |

Вне объёма, как и в ТЗ: онлайн-бронирование и оплата, CRM, письма-подтверждения, загрузка фото через редактор.

## Безопасность

- Пароль администратора и токен бота хранятся только в переменных окружения и никогда не отдаются в браузер. Тест A17 это проверяет.
- Строгая Content-Security-Policy без inline-скриптов, `X-Frame-Options: DENY`, `nosniff`, HSTS в production.
- В форме есть скрытое поле-ловушка для спам-ботов. Такие заявки принимаются «молча» и в Telegram не уходят.
- Если токен бота где-то засветился, сгенерируйте новый в @BotFather командой `/revoke` и обновите переменную в обоих сервисах.
